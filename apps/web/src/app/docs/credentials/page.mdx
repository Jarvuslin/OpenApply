# Credentials

Employer portals can require an account. Save a credential scoped to that employer's domain under **Settings → Credentials**. The agent uses it only for the intended portal. A failed saved login asks for help and never triggers an automatic password reset.

LinkedIn, Indeed, Glassdoor, ZipRecruiter, Upwork, Handshake and Wellfound are blocked for browser automation and credential storage. Discovery from these boards must use an optional HTTP connector. Your own LinkedIn profile URL remains a valid field on employer forms.

## Mailbox access

Connect Gmail through your agent, then use **Check Gmail with Claude Code** or **Check Gmail with Codex** in **Settings → Email** or the workbench's **Connections** tab. See [Email setup](/docs/email-setup). The provider manages authorization; OpenApply stores the messages the agent imports.

## Discovery keys

In **Connections → Optional job discovery**, enable SerpApi or Apify with your own API key. Apify also needs your chosen actor and compatible input fields. Searches can spend provider credits. They do not use your browser cookies or board session.

## CAPTCHA services

Solver keys remain available in the credential vault, but solving is disabled by default. The API entitlement must be enabled before the agent can invoke a solver. Disabled or unsuccessful solving parks the job, leaves its browser tab open and continues to another approved job.

## Secret storage

The API encrypts stored employer credentials, discovery keys, solver keys and legacy OAuth tokens using a per-user key. Deleting an account destroys that key. Do not commit secrets or put them in job descriptions.

## Application limits

The standing Discover queue has no per-campaign cap. Other campaign types can still have user-defined limits, and the Pilot keeps its existing daily policy. Missing facts, uncertain fit or blocking verification can pause an individual job.
